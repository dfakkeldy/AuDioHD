# Changelog

All notable changes to Echo: Audiobook Study Player.

## [Unreleased]

- Narration improves satisfied-versus-material “content” handling, marks exact
  contextual word occurrences, and supplies adjacent paragraph context for
  explicit shadow audits. Ordinary rendering no longer waits for shadow model
  inference. Identifier normalization preserves source characters, G2P planning
  reuses bounded results, and CLI renders without word timings skip the duration
  model. Added synthetic listening/benchmark tooling; automatic model pronunciation
  choices remain pending qualification. See `docs/narration-context-and-performance.md`.


### Added
- **EPUB pronunciation annotations and PLS lexicons:** EPUB authors can specify pronunciation without respelling the text shown in the reader, search index, or alignment sidecar. Inline SSML IPA spans (`ssml:ph`) and document-linked, manifest-declared PLS lexicons survive import and feed the shared app/headless synthesis planner. Explicit user occurrence, then per-book, then global corrections still win over inline EPUB instructions, then PLS entries; automatic handling remains the fallback. This is Echo’s English/Kokoro authoring subset (`epub.*.ipa-v1`), not complete SSML, PLS, or multilingual IPA support. Invalid annotations reject the annotated import with an explicit error (no silent drop). Changing IPA, or adding or removing annotations, invalidates the affected audio-cache signature; reimport the EPUB to pick up edits. Authoring contract: `docs/epub-pronunciation-authoring.md`. Audiobook skills are unchanged.
- **PDFs can be narrated from the Mac app.** On-device narration of a PDF's extracted text has worked in `echo-cli narrate` and the headless runner since PDF import landed, but the Mac app could never reach it: the narrate open panel offered no PDF `UTType`, the folder sweep matched only `.epub`, and `MacBatchProcessingService` fell a queued PDF through to `EPUBImportCoordinator`, which failed it as an empty import. Batch ▸ "Narrate Documents…" (renamed from "Narrate EPUB(s)…", still ⌘⌥N) now accepts `.pdf` alongside EPUB and Markdown/plain text, a selected folder is swept for both `.epub` and `.pdf` (`FolderAudioScanner.narratableDocumentExtensions`), and the queue routes PDFs through the shared `PDFAutoImportScanner.importPDFFile` with `force: true` — matching the headless runner, so re-queuing an item re-extracts instead of silently taking the "blocks already exist" fast path. Everything downstream was already extension-agnostic (it reads `epub_block` rows, and the sidecar path just swaps the extension), so read-along, chaptered playback, and `.m4b` export come along unchanged. No schema change. New tests: `MacImportParityTests.batchNarrationImportsPDFsThroughTheSharedScanner` and `.batchNarrationAcceptsPDFSelections`.
- **Organized, reliable Audiobookshelf browsing and imports (iOS + macOS):** both platforms now share Newest Added, Title, Author, Series, and Publication Year sorts; searchable multi-select Author, Series, Genre, and Tag filters; **Not Added to Echo**; exact or clearly limited result counts; retained paging; and matching empty states. Imports now show transferred bytes plus staged Downloading, Extracting, Validating, and Adding to Echo progress, keep named failures visible with Cancel/Retry, and report Added only after supported local content and active-server provenance are verified. Success no longer sends the user back to Connections: the Added state remains available until **Open in Echo** is chosen explicitly, and a failed re-import preserves the previous completed copy. Streaming and fully resumable background transfers remain out of scope.
- **Anthology chapter narration voices:** Chapters can inherit Echo’s preferred narration voice or keep an explicit per-chapter override, with the same choices editable on iPhone, iPad, and Mac. Reordering an unchanged anthology now reuses its stable narration files while updating playback and export order.
- **Per-chapter voices in `echo-cli narrate`:** repeat `--chapter-voice N=voice_id` to override the default `--voice` for selected 1-based narrated chapters. Mixed-voice runs bind the complete ordered voice plan into capture/resume identity, preserve each voice through parallel synthesis and M4B assembly, and emit schema-3 pronunciation audits with exact chapter-to-voice provenance. Invalid or duplicate assignments fail before fresh-run cleanup.
- **Experimental Now Playing player (iOS, opt-in) + tap-to-fullscreen / long-press-save artwork:** Settings ▸ Now Playing ▸ "Experimental Player Layout" (default off) swaps the iOS Now Playing tab for a full-bleed cover layout — the cover aspect-fills the top and dissolves into the existing cover-derived theme wash — with individual round Liquid Glass buttons (`GlassControlButton`, iOS 26 `.glassEffect` with an `.ultraThinMaterial` fallback for iOS 18–25) you can configure. Each button wraps an existing `WatchAction`; placement snaps to one of seven fixed anchors (`PlayerSnapZone`) with a bounded fine-tune offset, resolved by the pure `PlayerZoneResolver`. Long-press any button (or `⋯ → Edit Buttons…`) to unlock edit mode: drag buttons between zones with intra-zone nudge, add/remove via a sheet and badge, and Done to lock. The arrangement is a small Codable `ExperimentalPlayerLayout` persisted as JSON in `SettingsManager.experimentalPlayerLayoutData` (decode failures fall back to the default set; lock state is transient; Settings ▸ "Reset Button Layout" restores defaults). The shared `UnifiedBottomDock` stands down only on this tab; Reader and other tabs keep the dock, and macOS/watchOS players are untouched (new views are `#if canImport(UIKit)`; the model/resolver are platform-neutral). Independently, a reusable `ZoomableArtwork` component (tap → `FullscreenImageViewer` with pinch 1–4×, pan, double-tap, swipe-down dismiss; long-press → save to Photos) now wraps cover art in both players and reader images gain a "View Full Screen" action. A real add-only permission flow (`PhotoLibrarySaver` — `PHPhotoLibrary.requestAuthorization(for: .addOnly)` + `PHAssetCreationRequest`, with a denial alert pointing to Settings and a success haptic) replaces the previous fire-and-forget `UIImageWriteToSavedPhotosAlbum` reader path; the `NSPhotoLibraryAddUsageDescription` string is broadened accordingly. New types: `ExperimentalPlayerLayout`/`ExperimentalPlayerButton`/`PlayerSnapZone`, `PlayerZoneResolver`, `GlassControlButton`/`GlassCircleBackground`, `ExperimentalNowPlayingView`/`FullBleedCoverBackground`/`ExperimentalControlLayer`, `ZoomableArtwork`/`FullscreenImageViewer`/`FullscreenImageItem`, `PhotoLibrarySaver`. New tests: `ExperimentalPlayerSettingsTests`, `ExperimentalPlayerLayoutTests`, `PlayerZoneResolverTests`, `PhotoLibrarySaverTests`. Design/plan: `docs/superpowers/specs/2026-07-19-experimental-now-playing-player-design.md`, `docs/superpowers/plans/2026-07-19-experimental-now-playing-player.md`.
- Coding-textbook support: EPUB `<pre>` and Markdown fenced code now import as
  code blocks — shown as monospaced, selectable cards in the reader and the
  Visual Listening stage, and narrated as a short caption cue ("Code listing."
  or the book's own listing caption) instead of being read aloud as word soup.
  CRLF/CR Markdown fences, structured `<figcaption>` text, and spaced or
  semicolon-terminated `brush:` language hints parse consistently; code cards
  use adaptive text colour, and image/code timing controls now share the generic
  "Visual timing" label. Commercial-audio alignment excludes raw listings in
  on-device, continuous, source-backed, and macOS DTW paths, and code contributes
  zero weight to audio-chapter estimates. Existing books pick this up on re-import.
- **Slideshow video export (iOS, macOS, echo-cli):** Books with alignment or narration can export the Visual Listening slideshow as a standard video bundle — `<Title>.mp4` (1920×1080 H.264 with sparse variable-duration frames: figure, caption, subtitle with karaoke word emphasis), `<Title>.srt` (block-level sidecar subtitles split into bounded cues), and `<Title>.chapters.txt` (YouTube-style chapter list; MP4 chapter atoms are stamped when verified). A pure `SlideshowExportPlanner` samples `VisualListeningCueResolver` per track with player-identical scoping so the export cannot drift from the live stage; `VideoExportService` follows the m4b export's `ExportSource` audio spine. iOS exports from the dock overflow (progress + share sheet), macOS from the export menu (save panel + Reveal in Finder), and headless via `echo-cli export-video` (`--simple`, `--size`, `--range`; default 1920×1080).
- **Portrait slideshow video export (iOS, macOS, echo-cli):** The slideshow video export now offers a **1080×1920 (9:16) Portrait** format for full-screen phone viewing, alongside the existing 1920×1080 Landscape default, which remains the default everywhere. `echo-cli export-video` gains `--portrait` (mutually exclusive with `--size`); a custom `--size WxH` picks its layout by orientation (`height > width` → Portrait). Dimensions are validated up front (even, 180–4096px per side, ≤8,847,360px area, ≤4:1 aspect) and an H.264 capability preflight now runs before any source/database work, so an unsupported request fails fast with a clear error instead of a late writer failure. Code listings in the export now render as a bounded on-frame code card in both formats instead of falling back to cover art, and long captions/subtitles use bounded fitting with a trailing ellipsis and stable word-aligned karaoke paging instead of clipping or shifting mid-word. `.srt` and `.chapters.txt` remain byte-identical for the same export regardless of format.
- **Watch player: segmented whole-book progress, crown volume indicator, and threshold-only crown haptics:** The watch's whole-book ("total" mode) progress indicators are now chapter-aware — the linear bar renders one capsule per chapter/track and the ring around play splits into arcs at the same boundaries, both falling back to the classic solid style for single-chapter books or books with too many chapters to read at watch size. The iPhone ships interior boundary fractions (`bookBoundaryFractions`, capped at 40) in every watch state context, sourcing multi-track playlists from track starts and single-file M4Bs from embedded chapter markers. Turning the crown in volume mode now shows a transient HUD (variable-fill speaker glyph + accent-tinted gauge with a 0 dB notch) driven by an optimistic local mirror of the iPhone's output gain, reconciled from `outputGainDB` echoed in state replies. Crown haptics are reworked to fire only at real thresholds: system per-tick detents and the per-message directional haptic on `volumeDelta`/`scrubDelta` are gone, replaced by a `.click` on each 1/16 volume step (and rail landings) and a `.start` when the scrub dead-zone engages — all respecting the existing watch haptics setting. Crown `volumeDelta` messages are also coalesced (~80 ms) instead of one WCSession message per hair-tick, and a latent accumulator wrap-around bug that could slam the volume after long sessions is fixed. New shared types: `WatchCrownVolume` (gain math mirrored by both sides), `BookProgressSegmentMetrics` (pure segment layout); new watch views: `SegmentedLinearProgressBar`, `SegmentedProgressRing`, `VolumeIndicatorView`. New tests: `WatchCrownVolumeTests`, `BookProgressSegmentMetricsTests`, plus boundary/gain coverage in `WatchStateContextBuilderTests`.
- **Richer Apple Watch progress surfaces:** Echo now offers a rectangular Smart Stack/complication card with cover, title, playback state, percentage, and a bold progress gauge. Full-colour Smart Stack rendering uses the current cover-derived accent; system-coloured watch-face appearances retain WidgetKit tint. The circular complication has a thicker safely inset ring, while the Watch Pomodoro uses bolder rings and a larger adaptive two-digit hours/minutes/seconds countdown with complete VoiceOver state and a named Set Duration action.
- **`echo-cli export-blocks` — v2 sidecar-parity source-block export:** dumps an EPUB's visible source blocks as version-2 JSON, using the same import stack as sidecar generation and verification so external packaging tools can join portable anchor IDs to source text. A direct regular `.epub` records a lowercase SHA-256 over its exact archive bytes in `source.epubSHA256`; an expanded EPUB directory records explicit `null` and cannot satisfy file-bound consumers. PDFs, generic container directories (including directories containing an EPUB/PDF), nonregular inputs, and symbolic links are rejected before loading. New types: `BlockExportDocument`, `BlockExportSourceResolver`.
- **Word-level timings and source identity in generated alignment sidecars:** Echo-generated (narrated) `.alignment.json` sidecars now carry the synthesizer's known-true per-word times instead of throwing them away. `AlignmentSidecar.Anchor` gains an optional `words` array (`{word, start, end}`, absolute book time in the anchor's timebase, array order == `word_timing.wordIndex`) and an optional SHA-256 `sourceBlockIdentity`; absent optional keys preserve legacy decoding and old builds ignore the additions. Current estimated, macOS DTW, macOS batch-narration, and `echo-cli narrate` writers attach the portable source identity. `echo-cli narrate` exports words by default — only synthesis-time (`source == "synthesis"`) rows whose count matches the shared narrated block text — with a `--no-word-timings` opt-out, and the `wroteSidecar` progress line reports how many anchors carried words. Code verification, materialization, and import now all tokenize the resolved caption/`"Code listing."` fallback, so verifier-approved code words import as word-level rows rather than mismatching raw syntax. On import, `DocumentImportFinalizer` applies sidecar words as `word_timing` rows with source `"sidecar"` at confidence `0.9`; word-count mismatches keep interpolation and a later machine re-alignment supersedes them. Import and `echo-cli verify-sidecar` share one fail-closed policy for modern files: every identity-bearing anchor must resolve, carry an identity, and match canonical source fields before any anchors are replaced. Legacy suffix-only sidecars remain permissive for code-free sources, including dropping foreign blocks, but are reported as stale when a code-bearing re-import could have shifted `s<i>-b<j>` suffixes. Existing machine and human anchors are preserved on stale-source fallback. The verifier also checks supplied word arrays for non-empty, monotonic, in-range timing and matching shared source-token counts. New APIs include `AlignmentSidecar.Anchor.Word`, `AlignmentSidecar.sourceIdentity(for:)`, `NarratedBlockText`, and `WordTimingMaterializer.applySidecarWords`.
- **Estimated alignment sidecars for fallback narration packages:** `echo-cli sidecar-from-chaptered-audio` can now turn an EPUB/PDF source plus a chaptered `.m4b` or sorted directory of per-chapter audio files into a portable `.alignment.json` using the same EPUB/PDF import stack and `s<i>-b<j>` sidecar contract as native Echo narration. The estimator places block anchors by word-count interpolation inside each audio chapter and defaults confidence to `0.5`, keeping these packages visibly lower-confidence than synthesis-time native alignment. `echo-cli verify-sidecar` checks JSON shape, block resolution, monotonic timestamps, duration bounds, and non-empty chapter coverage before a fallback render is called Echo-ready. New types: `EstimatedAlignmentSidecar`, `AlignmentSidecarVerifier`, `ChapteredAudioTimingReader`, and `SidecarSourceBlockLoader`. New tests: `EstimatedAlignmentSidecarTests`.
- **Visual listening slideshow mode (iOS, iPad, macOS):** Now Playing can render an in-app visual listening stage for books with EPUB/PDF image blocks or imported code listings plus aligned text. A shared `VisualListeningCueResolver` selects the active visual payload (`image(path:)` or `code(text:language:)`), required subtitle/cue, karaoke-style word progress, and begin-vs-midpoint timing policy from existing `epub_block`, `timeline_item`, and `word_timing` data; `VisualListeningViewModel` loads those cues without a schema migration. iPhone keeps a compact single-column stage, iPad landscape gets a wider Now Playing layout with the visual stage beside metadata and controls, and macOS shows `MacVisualStageView` above the persistent reader feed in `MacTriPaneView`. The stage appears when a snapshot has either image or code visual content together with its subtitle/cue; system Now Playing artwork remains unchanged.
- **PDF figures on study cards:** PDF import now extracts embedded figures (`PDFFigureExtractor` — CoreGraphics content-stream scan for image placements + rect rasterization, so JPEG-2000 + soft-mask figures render correctly) and persists them as first-class `epub_block` image blocks via `PDFFigureImporter` (reusing `image_path` and `pdf_block_page`; `text` is nil so narration and read-along skip them), making any imported PDF's diagrams addressable by portable `s<i>-b<j>` anchors. The `.echo-deck.json` import format gains two optional, mutually-exclusive per-card image fields — `imageAnchor` (attach an in-book figure by anchor) and `imageFile` (attach a bundled image copied into per-deck storage) — resolved to `flashcard.media_json` in `DeckImportService` (non-fatal on I/O errors; bundled paths are traversal-guarded), and the general study review cards now render that image above the Q&A (iOS `FlashcardReviewCard`, macOS `StudyInlineReviewCard`, and the daily-review and checkpoint flows), via a shared `StudyLocalImageView`. No schema migration.
- **PR 406 UI cleanup and library edition grouping:** iOS now uses one bottom-dock More menu for player/app actions (chapters, bookmarks, add/replace document, M4B export, study-note export, stats, fidget, settings, and help); the old top-header ellipsis is gone, the folder chip appears only on Library, the sleep-timer pill is the single visible timer state, reader chrome hides as you scroll, empty alignment timestamps no longer render "None", and the mini-player strips noisy numeric track prefixes. The watch layout editor now uses localized action labels and inline slot pickers instead of the drag palette. Library scans prefer album/book metadata over track titles, backfill missing audio covers from companion EPUBs, and Schema V35 groups sibling audio/EPUB/PDF/text editions behind one shelf card with a sibling context menu plus "Separate This Edition" opt-out. EPUB import now keeps heading-bearing title/copyright/dedication-style front-matter pages out of content chapters, and no-audio TOC chaptering ignores front-matter anchors.

- **Auto-export study captures to a folder (Schema V34, Echo Pro):** Settings -> Study & Notes -> Auto-Export lets a Pro user pick a folder, and Echo keeps one Markdown file per book continuously mirrored inside an `Echo Study Notes/` subfolder. The mirror includes bookmarks, notes, and flashcards with YAML frontmatter, stable capture-ID markers, chapter attribution, and Echo deep links; it is deterministic, debounced on capture, flushed on backgrounding, atomically rewritten, SHA-skipped when unchanged, and backed by durable per-book dirty state when the folder is unreachable. Text-only in v1: voice memos, photos, card media, and bookmark location fields are deliberately not exported. Manual study-note export is unchanged. - **Narration render quality:** generated EPUB narration now plans speech and pauses explicitly before synthesis, retries low-quality speech chunks once, uses phoneme-budget render input chunking, materializes synthesis-time word timing, keeps word timing out of inserted silence, and exposes a local-only pronunciation preflight report.
- **FM pre-normalization for generated narration (Schema V32):** Generated narration now refines TTS input before synthesis when the Foundation Models path is available and the narration QA classifier setting is `auto`. The render path is `TextNormalizer.normalize()` → `FMNormalizer.refine()` → `PronunciationOverrides.apply()` → `NarrationTextChunker.split()`, so rules still handle deterministic cleanup, FM covers context-sensitive TTS traps, and user pronunciation overrides remain the highest-priority layer. Refined text is persisted in `epub_block.narration_text` (nullable; original `text` remains the source of truth), and `NarrationQAService` compares heard audio against `narrationText ?? text` so QA checks the exact text the TTS received. `FMNormalizationCache` dedupes repeated block refinements during a render run, and a hallucination guard rejects outputs that no longer resemble the source. `echo-cli narrate` adds `--db` so headless runs can persist/refetch FM-refined text and QA rows instead of using only the default in-memory database.
- **Audiobookshelf macOS progress sync + multiple saved servers (Schema V31):** macOS now has the first-class ABS sheet backed by the shared services, can save multiple servers, switch the active server without re-entering credentials, and remove saved servers with local token cleanup. `Schema_V31` adds `abs_server.is_active`; `ABSServerDAO.all()`/`setActive(_:)` preserve iOS's single-active-server behavior while enabling the macOS saved-server list. `MacPlayerModel+Audiobookshelf` owns a long-lived service cache for the active server, refreshes ABS identity on book load, pushes throttled progress while playing, and reconciles remote progress after local restore. Streaming and full background `URLSessionConfiguration.background` downloads remain deferred.
- **AI-generated study cards from a book's text (bring-your-own Anthropic key; iOS + macOS):** A model-backed study-deck generator turns a book's EPUB/transcript text into Q&A and **cloze** flashcards using your **own** Anthropic API key — stored in the Keychain (never UserDefaults, never logged) and called directly over HTTPS (no Echo account, no Echo servers). It is **opt-in** behind a one-time consent and gated on the key only (no Pro requirement; AI cards don't consume the free-tier cap); with no key, generation falls back to the existing deterministic generator, so the default on-device experience is unchanged. Generation is a two-pass pipeline (book-brief → spine-bounded chapter batches) behind a `StudyDeckGenerating` seam mirroring the narration-QA `DivergenceClassifier` pattern, with injection-hardened prompts (all source XML-escaped + framed as untrusted), `output_config.format` structured output, adaptive thinking, prompt-cached system prefix, and typed `refusal`/401/429 handling. Deterministic validation drops verbatim-copy, unknown-anchor, over-length, and invalid-cloze cards; per-batch failures recover (earlier cards survive); the run is cancellable with `(done,total)` progress (Cancel/dismiss stops generation). **Cloze** cards expand via `ClozeParser` into one row per deletion with `card_type='cloze'`/`cloze_index` — using columns that already exist in Schema_V1, so **no migration**. Settings (key entry, model picker — default `claude-opus-4-8`, with a Sonnet/Haiku option — and consent) live in iOS Settings ▸ Study & Notes and the macOS "AI" preferences tab. New types: `StudyDeckGenerating`/`StudyDeckGeneratorFactory`, `AnthropicStudyDeckGenerator`, `AnthropicMessagesClient`/`AnthropicClientError`, `APIKeyStore` (+ `KeychainStore.Key.anthropicAPIKey`), `StudyDeckPromptBuilder`, `StudyDeckBatcher`, `studyDeckHasValidClozeMarkers`/`studyDeckIsLongSourceQuotation`, `StudyDeckCardKind`, `AICardGenerationSettings`/`AICardGenerationSettingsView`, `StudyFlashcardType.cloze`. Design/plan: `docs/superpowers/specs/2026-06-30-ai-card-generation-design.md`, `docs/superpowers/plans/2026-06-30-ai-card-generation.md`. New tests: `StudyDeckGeneratorFactoryTests`, `APIKeyStoreTests`, `AnthropicMessagesClientTests`, `StudyDeckPromptBuilderTests`, `AnthropicStudyDeckGeneratorTests`, `StudyDeckBatcherTests`, `StudyDeckOutputValidationTests`, `GeneratedStudyDeckDraftTests`, plus cloze coverage in `StudyDeckAcceptanceServiceTests`/`StudyDeckGenerationViewModelTests`. *The opt-in AI feature sends the book's text to your chosen provider when used; the paywall's "no account, no servers, no tracking" line describes the default on-device experience — marketing-copy scoping is a separate owner decision.*
- **On-device AI study-card generation via Foundation Models (iOS 26 / macOS 26, no key, fully private):** A third generation provider, `FoundationModelsStudyDeckGenerator`, produces study cards entirely on-device using Apple Intelligence — no API key, no network calls, no text leaves the device. It is triple-gated: compile-time (`#if canImport(FoundationModels)`), OS version (`@available(iOS 26, macOS 26, *)`), and runtime (`StudyDeckFMAvailability.isAvailable`, mirroring the narration-QA classifier gate). The new `StudyDeckGeneratorFactory.make(preference:hasKey:fmAvailable:anthropic:)` overload selects among all three providers per `AICardGenerationSettings.providerPreference` (`.auto` = key wins → on-device FM → fixture; `.cloud` = BYO-key or fixture; `.onDevice` = FM or fixture). The provider preference is surfaced via an inline `Picker` inside a `Section("Provider")` in `AICardGenerationSettingsView`; the on-device option shows only when FM is available at runtime. On macOS the preference is configurable in the AI settings tab, but generation is currently triggered only from iOS book settings — the preference is settable but not yet actionable on macOS. No schema change. New types: `FoundationModelsStudyDeckGenerator`, `StudyDeckFMAvailability`, `StudyDeckFMCardMapper`, `StudyDeckGeneratorPreference`, `StudyDeckGeneratedCard`. New tests: `StudyDeckGeneratorFactoryMatrixTests` (6 matrix cases), `StudyDeckFMAvailabilityTests`, `StudyDeckFMCardMapperTests`.
- **Content-free term-level pronunciation contribution payload + privacy export filter:** `PronunciationContributionPayload` carries exactly five fields (term, ipa, language, voiceModelVersion, confidence) — no surrounding prose, audio, or book ids. `ContributionPayloadFilter` maps resolved single-word pronunciation QA fixes from M3 into payloads, dropping anything multi-word, unresolved, or missing IPA.
- **Opt-in contribution consent gate; transport is deferred/inert:** `ContributionConsent` defaults to not-decided; `ContributionConsentGate` enforces explicit opt-in. `DeferredContributionTransport` is a documented stub that returns `.blockedNoConsent` or `.deferred` — nothing leaves the device. No CloudKit, no networking.
- **Local public-domain regression-corpus test harness (out-of-repo fixtures):** `RegressionCorpusHarnessTests` is gated on `ECHO_REGRESSION_CORPUS_DIR` — skipped by default, runs public-domain fixtures through the deterministic `NarrationQADetector` when the env var is set. No fixtures committed.
- **On-device transcription of audio-only books (Schema V29):** Audio-only imported books (M4B/MP3 without a companion EPUB or text) can now be transcribed on-device with WhisperKit and opened in the read-along reader with word highlight, search-to-seek, tap-to-seek, and study anchoring. `StandaloneTranscriptionService` drives per-chapter, resumable transcription; `TranscriptMaterializer` projects results into `epub_block`/`timeline_item`/`word_timing` with `transcript-` prefixed block ids and `word_timing.source = "transcript"`; `TranscribeBookCoordinator` owns the end-to-end flow. Schema V29 adds `audiobook.text_origin` set to `"transcript"` to mark provenance so M2 never treats the book as canonical source. Transcript reader parity verified by `TranscriptReaderParityTests`.
- **Source-backed transcript alignment (M2, code-only):** Books that already have canonical source text (EPUB/PDF import) AND on-device transcription can now be aligned by reusing `TokenDTW` + `AnchorSelector` + `WordTimingMaterializer` without re-running WhisperKit. `SourceBackedAlignmentCoordinator` reads ASR words from `standalone_transcript` rows, runs the same DTW alignment pipeline as auto-alignment, writes `.transcriptAlignment` anchors, and refines word timing from DTW matches. Low-confidence word spans are flaggable via `lowConfidenceWordCount(threshold:)`. New types: `SourceBackedAlignmentCoordinator`, `AlignmentAnchorRecord.Source.transcriptAlignment`, `AlignmentAnchorDAO.deleteAnchors(for:source:)`. No schema change.
- **Generated Narration QA (M3, Schema V30):** After narrating an EPUB/PDF, a user-initiated "listen back" QA pass re-transcribes the generated audio with WhisperKit, compares heard words to source text via `TokenDTW.wordMatchesWithBisection`, and persists reviewable `narration_quality_issue` rows for any detected divergences. The deterministic `NarrationQADetector` + `DeterministicDivergenceClassifier` produce device-independent issue sets; a triple-gated `FoundationModelsDivergenceClassifier` enriches labels with spoken-form/IPA suggestions on supported devices (iOS 26+). The `narrationQAClassifier` setting (`auto`/`deterministic`) controls which classifier is used. `NarrationQAReviewView` (iOS) lists issues with swipe-to-resolve/ignore. New types: `NarrationQADetector`, `DivergenceClassifier` protocol, `DeterministicDivergenceClassifier`, `FoundationModelsDivergenceClassifier` (gated), `DivergenceClassifierFactory`, `NarrationQAService`, `NarrationQualityIssueRecord`/`NarrationQualityIssueDAO`, `NarrationQAReviewModel`/`NarrationQAReviewView`, `DivergenceWindow`, `DivergenceClassification`, `SuggestedFix`.
- **Send a book's EPUB to the EchoDeckBuilder companion app (iOS + macOS):** A handoff opens the current book's `.epub` in the **EchoDeckBuilder** Mac app to build flashcard decks. On iOS, **Book Settings ▸ "Make Flashcards in EchoDeckBuilder"** shares the resolved `.epub` via the share sheet; on macOS, the player's **More ▸ "Open in EchoDeckBuilder"** resolves the `.epub` and launches the app via `NSWorkspace` (with an install hint if it isn't found). A shared, pure `EchoDeckBuilderHandoffService` resolves which `.epub` belongs to the loaded book — preferring a directly-opened `.epub`, then a standalone EPUB book, then a sibling whose name matches the current track or the opened document — and **refuses to hand off an unrelated sibling** when you opened a non-EPUB document (PDF/Markdown/text). The action is gated on a *real resolved `.epub`* (not `hasEPUB`, which is also true for parsed PDF/.md/.txt books), so audio-only and text-only books show it disabled rather than failing on tap. New `PlaybackState.sourceDocumentURL` tracks the directly-opened document; new `EchoDeckBuilderHandoffServiceTests`. No schema change.

- **Playback controls stay responsive while an EPUB book loads:** Opening a book with an EPUB used to freeze the whole UI — including the play button — for several seconds on older phones (reported on iPhone 12), because the entire per-open pipeline ran synchronously on the main actor: the full `timeline_item` rebuild (`TimelineIngestionService.ingestItems`), `AlignmentService.recalculateTimeline` plus the whole-book `word_timing` re-materialization (one row per word of the book), the auto-import scan (which decoded **every** block row just to check "already imported?"), the first-open unzip + XHTML parse + block import, and the reader feed's `reload()` (all blocks + all word timings again). - **Sentence-initial imperatives no longer take the noun pronunciation in on-device narration.** Apple's part-of-speech tagger reads a capitalised heteronym at the start of a sentence as a noun or adjective even when an object follows, so Kokoro said "PER-mit me", "close (klōs) the door", "PRO-ject the image", "SEP-arate the eggs", "use (yoos) it wisely". The vendored MisakiSwift G2P now retags that exact shape — a gold-lexicon part-of-speech heteronym directly followed by a determiner or object pronoun at sentence start — as a verb before lookup, so the lexicon's `VERB` entry wins. Relative-clause shapes ("Content that is useful…", "Progress we made…"), noun modifiers ("Record high temperatures"), punctuation-separated pairs ("Record: the history…"), all-caps tokens, and authored `[word](/ipa/)` pronunciations are untouched. Measured on ~120 heteronym sentences before the change: the tagger flips these same words to verbs as soon as anything precedes them and a preceding sentence does not help, so this is a sentence-initial prior, not missing context. `NarrationFileNaming.renderVersion` 23 → 24 so cached narration regenerates once. New `ImperativeHeteronymTests` in `ThirdParty/MisakiSwift`. - **Narration: multi-second silent gaps eliminated (the model's all-zero output is caught and recovered):** The Kokoro ONNX model intermittently returns a full-length but **all-zero** waveform for a chunk — landing as pure digital silence in the narrated audio (measured at ~10–12% of chunks on *Git Happens*, some clustering into gaps up to 24 s, ~20% of the book overall). `OnnxKokoroEngine` now routes every synthesis through `NarrationSilenceGuard`, which detects a silent (non-empty, near-zero-peak) result and recovers — first re-running at a slightly nudged speed (the deterministic CPU EP repeats the zero on identical input, so recovery changes a model input rather than re-running verbatim), then splitting the text at a word boundary — so a real word is never dropped to silence. - **Narration: choppy "periods everywhere" prosody reduced — fewer, longer chunks and prosody-aware silent-chunk recovery.** Each `synthesize` call is an independent utterance whose final word gets sentence-final intonation, so every chunk seam is an audible pause; the all-zero recovery (above) made this worse, because it re-synthesizes a silent chunk's halves *separately* and the model's zero is deterministic per input, so the split fires on ~10% of chunks. Three changes: (1) the per-call budget rises from **200 to 350 characters** — the 200-char cap guarded against a FluidAudio/CoreML ANE BNNS trap that no longer exists on the ONNX Runtime CPU engine, and 350 chars (~350–455 phonemes) stays safely under Kokoro's ~510-phoneme context window — roughly halving the number of chunk seams (and, since the all-zero bug is ~per-call, the number of recovery splits); (2) a silent chunk is now first retried with a **small, inaudible speed nudge** (±3%) on the whole fragment — one utterance, no seam — so an all-zero output specific to the model's `speed` input recovers with no prosody cost before any split; (3) when a split is still unavoidable, `NarrationSilenceGuard` now splits at the nearest **clause/sentence boundary** (`, ; : . ! ?`), never inside a `[word](/ipa/)` override link, so the seam lands where a pause sounds natural.
